# Project State

Consolidated knowledge about what the Customer Portal application currently
does. Updated by `story-orchestrator` during **archive mode** (registry key
`project_state`), only after explicit human approval of the proposed changes.

Do not edit this file as part of a normal delivery stage — it reflects
*delivered and archived* capability, not work in progress.

## Delivered Capabilities

_None yet._ The repository is a scaffold: the directory structure and empty
module files for `auth` and `users` exist, with no business logic, no routes
wired, and no tests.

## Known Constraints

- `prisma/schema.prisma` is a placeholder — no datasource, generator, or models
  yet. The first Story that touches persistence introduces them together with
  the first migration (see `docs/architecture/persistence-conventions.md` PC-2).
- `src/config/env.ts` and `src/lib/prisma.ts` are placeholders; startup
  validation and the Prisma singleton do not exist yet.
- CI (`.github/workflows/ci.yml`) runs the full set from `AGENTS.md` "Build and
  Validation Commands" on push to `main`/`master` and on every pull request,
  harness checks first; every step is blocking. It has **no `services: postgres`
  block yet** — that arrives with the first database-backed test (PC-1). The
  repository has no remote yet, so the workflow has never executed — it is
  configured, not proven.
- Test infrastructure: Vitest is configured (`vitest.config.ts`,
  `tests/support/setup.ts`) and runs; `tests/harness.test.ts` is the only test
  that exists. There are no application tests. **A test database does not exist
  yet**, but the strategy is no longer open: it was decided on 2026-09-01 and is
  recorded in `docs/architecture/persistence-conventions.md` PC-1. The plumbing
  (compose service, `.env.test`, `globalSetup`, truncation fixture, CI service
  block) is owed by the first Story that needs database-backed tests, so
  `tests/integration/` is empty until then. See `tests/README.md`.
- `npm audit` reports 3 high findings in one chain: `prisma` (CLI) →
  `@prisma/config` → `deepmerge-ts` (stack exhaustion when merging recursive
  object graphs). Reviewed 2026-08-31 and **accepted**: the only input to that
  merge is our own committed Prisma config, there is no attacker-controlled
  path, and no fixed release exists on Prisma 7.10 (npm's suggested "fix" is a
  downgrade to Prisma 6). Re-check when Prisma publishes an update. The
  acceptance is recorded by advisory id in `.audit-allowlist.json`;
  `npm run audit:check` fails on any high/critical advisory that is not listed,
  and equally on a listed one that has been fixed upstream.
- The OpenAPI generator is wired (`src/lib/openapi.ts`,
  `scripts/generate-openapi.ts`, `npm run openapi:generate` /
  `npm run openapi:check`) and `docs/api/openapi.json` is committed. No module
  registers an operation yet, so the document has empty `paths`; the drift gate
  runs in the Stop hook and in CI and starts biting with the first schema.
